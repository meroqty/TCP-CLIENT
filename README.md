# Домашнее задание №3. Клиент–сервер «Калькулятор»

**Язык:** C (POSIX sockets)  
**Файлы:** `server.c`, `client.c`  
**Адрес:** `127.0.0.1`  
**Порт:** `9000` (по умолчанию)

## Протокол обмена

Используется текстовый протокол в кодировке **UTF-8**. Каждое сообщение заканчивается одним байтом перевода строки `\n` (hex `0A`). Максимальная длина полезной части сообщения — 16384 байта. Ввод калькулятора состоит из цифр, точки в десятичной дроби, пробелов, скобок и операций `+`, `-`, `*`, `/`. Вычисления с обычным приоритетом операций, скобками и унарным минусом. Дробная часть отделяется точкой.

**Запрос:** выражение и `\n`.

**Успешный ответ:** `OK `, десятичное число и `\n`.

**Ответ об ошибке:** `ERR `, код ошибки и `\n`.

Коды ошибок:

- `invalid_expression` — выражение записано неверно;
- `division_by_zero` — деление на ноль;
- `too_long` — запрос превысил ограничение длины или содержал нулевой байт.

Пример обмена:

```text
Клиент → Сервер: 12+30*2\n
Сервер → Клиент: OK 72\n
Клиент → Сервер: 8/0\n
Сервер → Клиент: ERR division_by_zero\n
```

Первый запрос в шестнадцатеричном виде: `31 32 2B 33 30 2A 32 0A`.  
Первый ответ: `4F 4B 20 37 32 0A`.

Клиент и сервер читают данные через цикл `recv()` до `\n` и сохраняют лишние уже полученные байты для следующего сообщения. `send()` повторяется до передачи всех байтов. Один TCP-пакет не считается отдельным сообщением.

## Сборка

Нужны компилятор C и POSIX-сокеты. Например:

```sh
cc -std=c11 -Wall -Wextra -o server server.c -lm
cc -std=c11 -Wall -Wextra -o client client.c
```

## Запуск

В первом окне:

```sh
./server
```

Во втором окне:

```sh
./client
```

Введите по одному выражению в строке; `exit` или `quit` завершает работу клиента. Сервер остаётся запущенным и может обслуживать следующее подключение. При желании порт и адрес задаются аргументами:

```sh
./server 9001
./client 127.0.0.1 9001
```

Пример ответов:

```text
12+30*2    → OK 72
3*4        → OK 12
(8-3)/2    → OK 2.5
8/0        → ERR division_by_zero
1++        → ERR invalid_expression
```

Можно отправить две строки сразу: `1+2\n3*4\n`; сервер выдаст два раздельных ответа `OK 3\nOK 12\n` в рамках одного TCP-соединения. Длинный запрос также принимается, если он не превышает ограничение.

## Обработка ошибок

- `socket`, `bind`, `listen`, `accept`, `connect` проверяются по возвращаемому значению.
- `send` и `recv` повторяются, если прерваны сигналом (`EINTR`).
- `send` записывает полный буфер циклом, учитывая частичную отправку.
- `recv` читает сообщение по разделителю `\n`, а не за один вызов.
- Закрытый порт (`ECONNREFUSED`), обрыв соединения и отсутствие ответа не приводят к аварийному завершению клиента.
- Сигнал `SIGPIPE` игнорируется, а ошибки отправки обрабатываются явно.

## Схема трёхстороннего рукопожатия TCP

```text
Клиент                                      Сервер
    ───────── SYN, seq=x ────────────────────>
    <──────── SYN-ACK, seq=y, ack=x+1 ────────
    ───────── ACK, ack=y+1 ───────────────────>
connect() вернул 0: соединение установлено.
```

`x` и `y` — условные начальные номера последовательности; при реальном захвате значения будут другими.

## Wireshark и скриншот для сдачи

Поскольку скриншот должен показывать **реальный захват с вашего компьютера**, его следует сделать при запуске программы:

1. Откройте Wireshark и выберите интерфейс loopback (для подключения к `127.0.0.1`).
2. Начните захват, затем подключите клиент к серверу.
3. Отправьте два выражения подряд, затем выйдите из клиента.
4. Введите фильтр отображения `tcp.port == 9000`.
5. Найдите `SYN`, `SYN, ACK`, `ACK`, пакеты с данными и закрытие `FIN/ACK`. Убедитесь, что между двумя запросами не было разрыва соединения.
6. Сделайте скриншот списка пакетов и приложите его к отчёту или архиву.

**Важно:** скриншот Wireshark не включён в этот комплект: он должен быть сделан из настоящего захвата, а не нарисован.
